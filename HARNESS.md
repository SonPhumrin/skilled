# Running skilled in a harness

What a coding-agent harness (a desktop or web app that drives Claude Code, Codex, ACP agents, or its own loop) must do to run these skills correctly, at the lowest context cost. Claude Code already does all of it natively; this is the contract for everything else, including a harness you build yourself.

## The catalog: `skills.json`

`skills.json` at the repo root lists every skill. Read it instead of parsing `SKILL.md` frontmatter. It is generated by `python3 tests/validate_skills.py --emit-index`, and the validator fails when it is stale.

| Field | Meaning |
| :--- | :--- |
| `name` | Skill name, equal to its directory under `skills/`. |
| `description` | For `model` skills: the trigger text the model sees. For `user` skills: a one-line summary for a human scanning a menu. |
| `invocation` | `model`: listed to the model, which loads it when the task matches. `user`: only a person starts it. |
| `argumentHint` | Optional. Placeholder text for what to type after `/name`. |
| `compatibility` | Optional. What the skill needs from the harness (subagents, background agents) and how it degrades without it. |
| `calls` | Skills this one loads with the Skill tool. Always `model` skills (CONVENTIONS.md, "dependency invariant"). |
| `files` | Every file in the skill directory, `/`-separated. `SKILL.md` is the entry point; the rest load only when the body points at them. |
| `sha256` | Fingerprint of the whole directory, to detect a changed or stale copy. |
| `alwaysOnChars` (top level) | Characters of name + description the model skills put in every session. |

## The contract

1. **List only `model` skills to the model**, as name + description. Nothing else about a skill is in context until it loads.
2. **Serve `user` skills yourself.** Show them in the harness's own `/` menu, with `argumentHint` as the input placeholder. When the user picks one, put the full `SKILL.md` body into the prompt, followed by whatever they typed after the name. Never list them to the model.
   Because a `model` skill never calls a `user` one, install only the model skills into the agent's own directories (`install.py --model-only`) and serve the rest from `skills.json`. They then cost zero context on every agent, including OpenCode and Antigravity, which ignore `disable-model-invocation`.
3. **Provide a skill-loading tool.** Skill bodies say `Call the Skill tool with "x"`. Claude Code's tool is `Skill`, deepseek-harness's is `skill`, and Codex reads `SKILL.md` from the path in its catalog; all three satisfy the phrasing. A harness with its own loop exposes one tool that takes a name and returns that skill's `SKILL.md` body plus its directory path, so relative links in the body resolve.
4. **Load supporting files lazily.** A body that links `reference/foo.md` expects the agent to read it only when that branch applies.
5. **Subagents and background agents.** `implement-spec`, `research`, `decision-map`, and `handoff-to-agent` use them; their `compatibility` field says how to degrade without them.
6. **A pre-tool hook** for `git-guardrails`: before a shell command runs, pass `{"tool_name": ..., "tool_input": {"command": ...}}` as JSON on stdin to `skills/git-guardrails/scripts/block-dangerous-git.py`, and treat exit code 2 as deny, with stderr as the reason.
7. **Optional: built-in browser tools.** If the harness has an in-app browser, expose it to the agent as `browser_open`, `browser_snapshot` (text with element refs like `e3`, not an image), `browser_click`, `browser_type`, `browser_eval`, `browser_logs` (console errors and failed requests), and `browser_screenshot` (saves a file; returns the image only when asked). An MCP prefix on the names is fine (`mcp__unskilled__browser_open`). `verify-in-browser` uses them when present and falls back to `agent-browser` otherwise. Attach them only once the user has opened the browser, so they cost nothing the rest of the time. UnSkilled (`apps/unskilled`) is a reference implementation.
8. **Optional: a reviewer on a different provider.** `review-diff` runs its Spec axis on a different model provider for high-risk diffs when the harness offers one.

## Installing into a project the harness manages

```bash
python3 install.py /path/to/project --claude --codex --model-only --vendor
```

`--claude` covers `.claude/skills` (Claude Code, and OpenCode's native scan). `--codex`, `--dsh`, and `--antigravity` all cover `.agents/skills`. `--vendor` copies real files, so the project doesn't depend on this checkout's location. `--uninstall` with the same harness flags removes exactly what was installed.
